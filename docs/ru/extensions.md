# Расширения

Встроенные расширения включены по умолчанию и не требуют никакой
настройки.

## Markdown-шорткаты

Срабатывают в начале блока (любого из `<p>`, `<div>`, `<h1>`-`<h3>`,
`<blockquote>`, `<pre>`, `<li>`):

| Ввод | Результат |
|---|---|
| `# ` | `<h1>` |
| `## ` | `<h2>` |
| `### ` | `<h3>` |
| `- ` или `* ` | `<ul><li>` |
| `1. ` | `<ol><li>` |
| `> ` | `<blockquote>` |
| ` ``` ` | `<pre><code>` |

Последовательность-триггер (например, `## `) удаляется из текста.

## Slash-команды

Введите `/` в начале блока — появится popup с командами:

- `/h1`, `/h2`, `/h3` — заголовок
- `/list`, `/ul` — маркированный список
- `/ol` — нумерованный список
- `/quote` — цитата
- `/code` — блок кода
- `/hr` — горизонтальная линия
- `/table` — вставить таблицу

Свои пункты хост добавляет пропом `slashCommands`; они идут в списке
после встроенных.

Чтобы отфильтровать, допечатайте символы (`/h2`). ↑/↓ — навигация,
Enter — выбор, Esc — отмена.

## Превью блоков (диаграммы, графики)

Блок кода может показываться тем, что он рисует. Передайте отрисовщик на
каждый язык:

```ts
import { render, DiagramError } from '@dskripchenko/diagrams'
import type { BlockRenderers, SlashCommand } from '@dskripchenko/wysiwyg'

const blockRenderers: BlockRenderers = {
  mermaid: (code) => {
    try {
      return { html: render(code).svg }
    } catch (e) {
      if (e instanceof DiagramError) return { error: e.message }
      throw e
    }
  },
}

const slashCommands: SlashCommand[] = [{
  key: 'diagram',
  label: 'Diagram',
  aliases: ['mermaid'],
  apply: (c) => c.chain().focus().insertCodeBlock('mermaid', 'flowchart LR\n  A --> B').run(),
}]
```

```vue
<DskWysiwyg v-model="html" :block-renderers="blockRenderers" :slash-commands="slashCommands" />
```

- `<pre><code class="language-mermaid">` показывается диаграммой, код скрыт.
- Клик по диаграмме открывает код с живым предпросмотром под ним. При вводе
  диаграмма перерисовывается после короткой паузы. Escape или уход курсора
  из блока закрывает код.
- Если рендерер отвечает `{ error }`, код остаётся открытым, а сообщение
  показывается под ним.
- Backspace по показанной диаграмме удаляет её вместе с кодом; отмена
  возвращает и то, и другое.
- В режиме readonly диаграммы показываются, но не открываются.

Хранимый HTML не меняется никогда: `getHTML()`, v-model, история и
`htmlToMarkdown` видят только блок кода (` ```mermaid `). Превью —
нередактируемый островок, который редактор сам добавляет и убирает.

Рендерер следует контракту `blockRenderers` из UidMarkdown кита:
`(code, { language, index }) => { html?, error? }` или промис с этим
результатом, так что один реестр обслуживает оба компонента. `html`
вставляется как есть, и за его безопасность отвечает рендерер. Сам
редактор не зависит ни от какой библиотеки диаграмм.

### Живые блоки (виджеты)

Вместо `html` рендерер может вернуть `mount`. Тогда в островке живёт
виджет — форма, конструктор запроса, — и он же служит редактором блока:

```ts
const blockRenderers: BlockRenderers = {
  api: () => ({
    mount: (el, { code, editable, setCode }) => {
      const widget = createWidget(el, { code, readonly: !editable, onChange: setCode })
      return { update: (next) => widget.setCode(next), destroy: () => widget.unmount() }
    },
  }),
}
```

- Код остаётся скрытым и не раскрывается: виджет меняет его через
  `setCode(code)`, а редактор записывает это одним шагом истории и эмитит.
- Undo и redo меняют код снаружи — виджет получает его в `update(code)`;
  без `update` виджет монтируется заново.
- Клавиши, ввод, вставка и клики внутри виджета остаются ему — редактор
  не считает их своими.
- В режиме readonly `editable` равно `false`, а `setCode` игнорируется;
  смена режима монтирует виджеты заново.
- `destroy` вызывается, когда блок удалён, заменён отменой или редактор
  размонтирован.

Контракт (`BlockMountContext`, `BlockMountHandle`) — тот же, что у
UidMarkdown из кита, поэтому рендерер, зарегистрированный один раз,
работает в обоих.

## Подсветка синтаксиса кода

Блоки `<pre><code class="language-{lang}">` подсвечиваются по blur.
Поддерживаемые языки: `js`, `ts`, `tsx`, `jsx`, `php`, `html`, `css`,
`json`.

Подсветка реализована на регулярных выражениях по токенам (~5 KB). Для
экзотических языков уберите класс `language-` — блок останется
обычным кодом.

## Таблицы

`controller.insertTable(3, 4)` вставляет таблицу 3×4 с `<thead>` /
`<tbody>` / `<th>` / `<td>`. Когда курсор внутри таблицы, тулбар
показывает кнопки addRow / addColumn / remove (или используйте
контроллер).

## HTML→Markdown

```ts
import { htmlToMarkdown } from '@dskripchenko/wysiwyg'

const md = htmlToMarkdown('<h1>Hi</h1><p><strong>bold</strong> text, version 1.5</p>')
// '# Hi\n\n**bold** text, version 1.5'
```

HTML редактора превращается в CommonMark с таблицами и зачёркиванием из
GFM, причём так, что обратное преобразование даёт тот же документ, —
повторный проход ничего не меняет:

- заголовки h1–h6, абзацы, `**bold**`, `*italic*`, `~~struck~~`;
  `u`, `mark`, `sup`, `sub` остаются HTML (в Markdown их нет);
- inline-код с таким числом обратных кавычек, какое ему нужно; блоки кода
  в ограждении длиннее любой последовательности обратных кавычек внутри,
  язык сохраняется (` ```mermaid `);
- вложенные списки через отступы, несколько абзацев в одном пункте;
- цитаты, в том числе вложенные; таблицы с выравниванием колонок; ссылки
  и изображения с их title; `<br>` как жёсткий перенос (`\` в конце строки);
- текст экранируется только там, где символ означал бы разметку (`*`, `_`,
  `` ` ``, `[`, `<`, а также `#`, `-`, `1.` в начале строки): точки, тире и
  скобки остаются как написаны.

Островки превью редактора в результат не попадают.

## Режим исходного кода

Кнопка тулбара `[</>]` переключает между WYSIWYG и редактором сырого
HTML (`<textarea>` с оверлеем подсветки синтаксиса). При входе HTML
**форматируется** (переносы строк и отступ в 2 пробела между блочными
тегами). При выходе — **минифицируется** (пробелы между блочными тегами
схлопываются). В сохраняемом состоянии формы — минифицированная версия.

import { highlight } from '@dskripchenko/wysiwyg'
